# Decisions (one line each, newest last)

- Repo root is the FitCast root (clips were already at `assets/test/`); old rad-AR README moved to `ios/README.md`.
- MediaPipe 1.1.1 is what pip resolves for py3.11 on arm64; Tasks API (`PoseLandmarker`, `ImageSegmenter`) unchanged from 0.10.x, verified by running it.
- Own vectorized One Euro filter over the (33,2) array instead of the `OneEuroFilter` PyPI package: that package is frequency-based (no timestamps) and would need 66 objects per frame.
- Nose/eye visibility is NOT used as the primary back signal: MediaPipe reports ~0.98 visibility from behind on both clips. Shoulder order + width ratio decide; visibility is only a weak confirmer (threshold in config).
- Clothes mask is gated by the pose model's own person mask (`output_segmentation_masks=True`, +0.4 ms): the selfie segmenter labels background patches as "clothes" on the gray backdrop.
- Resize 4K->720p happens inside the capture thread with INTER_AREA (6 ms) so it overlaps model inference; INTER_LINEAR (0.4 ms) is selectable in config.
- rtmlib is an optional backend installed with `--no-deps` (its deps drag in a second OpenCV wheel). Its ONNX models are pre-downloaded by `scripts/download_models.py`; lightweight mode (16 ms) is the only one fast enough, balanced is 70 ms.
- Landmark "visible" = visibility >= threshold AND inside the frame by a margin: knees below the frame edge still report 0.68 visibility.
- Gallery panel is drawn in camera space (per spec) and warped with the rest; text blurs slightly but keeps one coordinate system and makes the "never overlap the person" check trivial.
- Sizing: chest is measured as a front-on width from the mask; the chart bounds are circumferences, so `sizing.chest_circumference_factor` (2.65) converts for both the chart lookup and the panel text.
- Sizing: on clips cropped above the knee the shoulder->hip span sets the scale, so the reported torso length is height x ratio, not a measurement.
- Calibration rescale (stored camera size != runtime size) uses cv2.resize's pixel-centre mapping x' = (x+0.5)*s - 0.5, not diag(s,s,1).
- `set_homography` reports RMS over all points; RANSAC rejections and inlier-only RMS go to the log so a mis-click is visible.
- The live calibration tool calls the same pure functions as `run_calibration` (capture_pattern, detect_markers, set_homography, verify_grid) so manual fallback and the gallery-rect step fit between detect and verify; `--simulate` and tests cover those functions.
- Gestures: a swipe needs >= `min_samples` buffered samples so a single-frame landmark jump cannot fire one.
- Garments: backs are made by pattern-aligned patch copy plus inpainted seams; plain `cv2.inpaint` smears stripes and plaid.
- Garments: `top_body_region` y-range is the garment's own alpha extent (imports are fitted with transparent padding, not stretched).
- Garments: the sleeve tile is sampled from the generated back so graphics/pockets never land on the arms; pants textures fill their width because the renderer splits legs at x = 0.5.
- Garments: the dress keeps a hip-level body region (bodice + top of skirt); a full skirt needs a leg-aware renderer part, deferred.
- `assets/garments/` is git-ignored (10 MB, rebuilt in <2 s); `main.py` regenerates the demo set automatically when the folder is empty.
- Mask `intersect` mode also unions (pose person-mask ∩ torso polygon): on white-on-gray side views the selfie segmenter drops chunks of the shirt side; the torso is always fabric so this is a safe fill (config `mask.torso_fill`).
- Fallback reference area is the previous frame's area (not an EMA) and 0 means 'no mask yet', otherwise the async segmenter's first result looked like a 400% jump and the skeleton fallback stuck forever.
- Segmentation runs in a worker thread (`seg_async`): one-frame mask lag, ~9 ms/frame hidden; `SegWorker` must not name a field `_stop` (shadows Thread._stop).
- Facing keeps two references (normalised by torso length when hips are visible, raw px otherwise) and adopts a width > 1.3x the reference at once; a single scalar reference was poisoned by a stretch of hidden hips and locked 'side' (review finding).
- `calibrate.py --simulate` writes `calibration_sim.yaml` with `simulated: true`; `Calibration.load` refuses simulated files unless the source is a video file (a fake H would put light on the face on the real rig).
- Main loop blanks the projector when no new frame arrives for `capture.stale_ms` and exits after `stall_exit_s`: never hold a stale garment frame on a moving person.
- In `side` state the renderer picks front/back texture by shoulder order (3/4-back poses showed the front graphic on the back).
- Torso fill subtracts the segmenter's body-skin class so bare arms across the torso and the neck strip are not lit.
- Gallery panel pixels are cleared against the dilated person mask (not just clothes) so a swiping hand entering the panel is not lit.
- Prediction horizon follows the measured capture->display latency (`smoothing.predict_auto`), clamped to `predict_max_ms`.
- Keys: `d` is debug-overlay only (was also 'next'); outfit keys are arrows + n/p.
- `mp.Image(..., data=arr)` copies `arr` (checked: zeroing the source after construction leaves `numpy_view()` intact), so the double-buffered RGB handoff to the segmenter worker cannot race even when submits are skipped.
- Demo idle timer resets on operator input (keys, swipes) only; `set_outfit` itself must not reset it or the auto-cycle waits `idle_s` between every change.
- Hips keep their visibility when they fall outside the frame (person close to the camera): the torso quad is anchored on the predicted hips and clipped by the frame; legs/arms still need in-frame landmarks. Sizing additionally requires the torso inside the frame.
- Live test with the MacBook camera (2026-10-17 17:07): 27 fps with debug+recording, 6 real swipes detected, tracking survives bystanders; the iPhone nearby takes camera index 0 and streams black when locked.
- Live: the camera must sit at the projector lens; the Mac lid camera beside the projector produced a 98 px (~10 cm) drop at the standing spot, fixed by `calibrate.py --refine` (probe discs on the tracked body). Any camera move invalidates both calibration steps.
- Live: tracking is restricted to the projector footprint (ROI from H) because bystanders near the lens hijacked the pose model and one refine run.
- Live: `cv2.waitKey`/`CATransaction.flush` block ~10-12 ms per call on the main thread; the projector frame is committed from a worker thread and the event pump runs every 2nd frame.
- Live: head box bottom is anchored to the chin (lowest face landmark + 0.30 SW) instead of the shoulder line; the neck/collar region is not the face and leaving it dark made every shirt look like it started too low.
- iOS signing from the CLI: the project's original team (KQ3W39U2QQ, a teammate's account) cannot mint profiles on this Mac; the user's personal team 7JCAPWSS7Z can (`xcodebuild ... -allowProvisioningUpdates` succeeded). FitCastSensor target uses it with bundle id `com.aadit.fitcast.sensor`.
- 3D path research (2026-10-17): phone is iPhone 17 Pro on iOS 27.2 beta (24B5089g), Mac has Xcode 26.2 / SDK 26.2 -> device deploy must be tested first. ARKit: `.sceneDepth`+`.personSegmentationWithDepth` combination is undocumented (check `supportsFrameSemantics` on the exact set; assigning an unsupported set throws an uncatchable NSException); depth arrives as DepthFloat32 (convert to F16 for the wire); 256x192 is community-reported only, read sizes at runtime. Vision: iOS 18 `DetectHumanBodyPoseRequest`, 19 joints, `toImageCoordinates(size, origin: .upperLeft)`; phone mounted landscape with USB-C on the right -> orientation `.up`. 3D Vision pose needs AVDepthData (no ARDepthData bridge) -> primary path is 2D Vision + LiDAR lift. Transport: iOS `NWListener` TCP; Mac side plain usbmuxd `Connect` over /var/run/usbmuxd (stdlib plist client, no RSD tunnel needed for port forwarding), pymobiledevice3 only as fallback (async API, churns daily). RGB: VTPixelTransferSession downscale + VideoToolbox JPEG (independent frames; HEVC would need PyAV). OpenCV `GrayCodePattern.decode` is stereo-only; `getProjPixel` returns an ERROR flag (True = invalid) and is too slow per pixel -> vectorised numpy decoder (verified 0 mismatches vs getProjPixel). Expected wire load ~15-19 MB/s at 60 fps.
